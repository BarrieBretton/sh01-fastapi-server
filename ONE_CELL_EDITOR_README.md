# Integrated Kaggle editor with inserted narration

This change targets `feature/ai-compose-kaggle` at remote commit
`fed2f61f15d91bdb8feaa94e2c17550a98160023`. It extends the existing
`POST /media/ai-compose` workflow; it does not change the production application's
router wiring or require a second caption service.

## Run one cell

Import `notebooks/sh01_full_editor_one_cell.ipynb` into Kaggle, or paste all of
`notebooks/sh01_full_editor_one_cell.py` into one Python cell. Enable **GPU** and
**Internet**, mount the source dataset, and run it. The default source is:

```
/kaggle/input/datasets/vivanjaiswal/video1/military_seth_raw_cut1.mp4
```

Edit the clearly marked configuration block at the top: source, brief, duration,
output resolution, narration sections, required features, libraries and models.
The code below that block is generated by `scripts/build_one_cell.py`; it embeds
inspectable Python source from this patch. It works without first pushing the
patch to GitHub or editing another notebook cell. Embedded code is extracted to a
separate versioned runtime directory; your existing checkout and `.env` are retained.

Setup creates a virtual environment that shares Kaggle's installed CUDA Torch,
installs other dependencies there, downloads public text/vision/TTS models, and
starts the notebook-only FastAPI app on loopback with a generated local key. No
paid AI API or stock-provider key is required. Optional provider credentials can
still come from your existing private `.env`. The cell's explicit configuration
wins over matching `.env` values. Text/vision use the GPU; ASR defaults to CPU to
avoid CUDA library mismatch, with `ASR_DEVICE='cuda'` available.

The first run requires network downloads. This automates setup; it is not a
promise of zero dependencies or unlimited free Kaggle compute. An interrupted
session cannot transparently resume inference. Completed outputs, receipts,
review history and asset credits are zipped under `/kaggle/working`. Save a
Kaggle notebook version with outputs to retain them. A cell cannot bypass a
browser's download confirmation or write directly to your laptop's filesystem.

Set `KEEP_LOCAL_API=True` to keep the API running after completion. Connection
information is written to the printed `local-api-private.json` path; it is
excluded from output archives. Stop the owned PID when you finish using it.
Default `False` shuts the server down cleanly after saving output.

## What changed

- `editor.narration` selects intro, intro/outro, or intro/bridge/outro inserts.
  The small local director writes grounded scripts. Piper synthesizes them first;
  actual WAV duration plus a short pause determines each slot. The selected source
  body has a separate duration budget. A bridge requires two source excerpts.
- Narration receives a dedicated animated vector title composition and silent
  base audio. Source excerpts retain their source timestamps and per-segment
  `audio_gain`. Narration does not replace or compete with the original speaker. The new insertion setting is independent of the legacy
  `voiceover.mode` overlay control; use `editorial_policy.voiceover="off"` to
  prohibit narration entirely.
- Body captions, graphic cues, visual layers and SFX are mapped around inserts.
  A layer spanning a bridge is split so it does not leak into the inserted section.
  Narration captions are transcribed from the synthesized audio.
- `editor.required_features` makes voiceover, SFX, music, camera motion,
  transitions, graphics, supplementary media and captions explicit completion
  requirements. Actual render counters and decode checks are retained. Conflicting
  off switches fail early. The notebook requests every feature and a local visual
  review; absence does not silently become a successful plain captioned clip.
- `editor.transition` and the director's `transition_style` select supported cut,
  dissolve, swipe or match/fade transitions. Section timing is preserved.
- Optional `asset_sources.wikimedia=true` retrieves Commons images/video without
  a key. Recognized reuse licenses, source URLs, credits and hashes are retained.
  Failed candidates get a bounded retry; missing video candidates may be retried
  as images. Local annotated libraries and keyed Pexels/Pixabay remain supported.
- Music can be a provided track or a locally synthesized ambient bed; SFX can be
  local files or procedural sounds. Music ducks under both original speech and
  generated narration. The procedural bed is not a generative music model.
- The existing ASR worker has an optional `--allow-empty` flag so silent/music-only
  material can be analyzed without falsely reporting a decoder failure. Existing
  callers retain their former behavior. Actual ASR errors still fail the job.
- Explicit captions/graphics/off settings retain their meaning. The renderer uses
  the requested CRF; integrated editing defaults to the `veryfast` x264 preset.

## Boundaries and validation

Motion graphics here are FFmpeg/libass vector animation, not a Remotion runtime
or arbitrary React/3D code generation. Claude commonly writes a Remotion project
and invokes its local renderer. Rendering is separate from the model's inference
service: Remotion needs no paid AI API key to render local code. Its own license
eligibility still applies. This editor uses local model inference instead.

All fields are bounded; unknown niches do not require new endpoints. Model quality,
asset relevance and aesthetic quality still depend on the footage, brief, models
and available assets. Commons metadata overlap is only a candidate score; sampled
frame review is not exhaustive face tracking, fact checking or an objective
measure of whether a reel will go viral. There is no promise that every arbitrary
prompt will pass the required-feature and visual gates.

Offline tests cover real FFmpeg rendering, source/voice frequency separation,
caption timestamps, overlays, narration budgets, missing-feature rejection,
script grounding checks, persistent receipts and failed-revision retention.
Local GPU inference, Piper downloads, live Commons/provider calls and the full
Kaggle setup are not executable in the development environment. They remain the
explicit end-to-end verification step in Kaggle; no generated demo is presented
as an edit of your private source.

Run validation locally (FFmpeg-dependent cases skip if FFmpeg is absent):

```powershell
python -m unittest discover -s tests -p "test_ai_compose*.py" -v
python scripts/build_one_cell.py
git diff --check
```
